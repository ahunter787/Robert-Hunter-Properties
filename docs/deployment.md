# Deployment

RHP runs as a Docker Compose stack — the **same application image** on a local VM and on a cloud
VPS. There is no "development version" and "server version" of the deployment: only Caddy and the
TLS/settings environment differ.

## Prerequisites

- A Linux host (Ubuntu/Debian assumed below), Docker Engine, and the **Compose v2 plugin**:
  ```bash
  docker --version
  docker compose version      # must print v2.x
  sudo apt-get install -y docker-compose-v2     # if the plugin is missing
  sudo usermod -aG docker "$USER"               # log out/in afterwards
  ```
- `git`, and either Node 22+/`uv` (see *Building on the host*) or a warm Docker build.
- Ports 80 and 443 reachable for a public deployment; 8000 for development.

## Topology A — local VM / Proxmox (LAN)

```
Proxmox host
  └── Ubuntu VM
        └── Docker Compose  ──  web (gunicorn) + db (PostgreSQL) + caddy
```

1. Clone the repository onto the VM.
2. `make env` and edit `.env`:
   - `DJANGO_SECRET_KEY` — already generated by `make env`.
   - `POSTGRES_PASSWORD` — already generated; keep it private.
   - `DJANGO_ALLOWED_HOSTS` — the VM's IP or internal hostname, e.g. `10.20.0.14,rhp.lan`.
   - `RHP_HOSTNAME` — the same name Caddy should answer on.
   - For plain HTTP on an isolated LAN, set `DJANGO_SECURE_SSL_REDIRECT=0` and
     `DJANGO_SECURE_PROXY_SSL_HEADER=0`. Cookies then stop being marked `Secure`, which is what makes
     sign-in possible over HTTP — **only** acceptable on a trusted network.
3. `make up-prod`
4. `docker compose -f docker-compose.yml -f docker-compose.prod.yml exec web python manage.py createsuperuser`

## Topology B — cloud VPS (public)

```
Internet → DNS A record → VPS (firewall 22/80/443)
                            └── Docker Compose ── caddy (TLS) + web + db
```

1. Point an A record at the VPS (e.g. `portal.roberthunterproperties.com`).
2. `make env`, then set:
   - `RHP_HOSTNAME=portal.roberthunterproperties.com`
   - `CADDY_EMAIL=<an address that receives certificate notices>`
   - `DJANGO_ALLOWED_HOSTS=portal.roberthunterproperties.com`
   - `DJANGO_CSRF_TRUSTED_ORIGINS=https://portal.roberthunterproperties.com`
   - keep `DJANGO_SECURE_PROXY_SSL_HEADER=1` and `DJANGO_SECURE_SSL_REDIRECT=1` (defaults)
   - SMTP settings, before Phase 1 sends anything to tenants.
3. Open 22/80/443 in the firewall (`ufw allow 22,80,443/tcp`); leave 5432 and 8000 closed.
4. `make up-prod` — Caddy obtains and renews the certificate automatically.
5. Create the first admin account (same command as above).

## What happens on start

`docker/entrypoint.sh` runs `migrate --noinput`, then `collectstatic --noinput`, then gunicorn
(`config.wsgi:application`, 3 workers, 60s timeout, logs to stdout). Static files land in the
`static_data` volume, which Caddy mounts read-only at `/srv/static` and serves for `/static/*`.

Media is **not** served by Caddy. Tenant documents and photos are served by permission-checked Django
views (Phase 6/7), so a guessed URL can never expose another tenancy's file.

## Routine operations

```bash
make up-prod                     # start/update the production stack
make down-prod                   # stop it (data volumes are preserved)
make prod-logs                   # follow application logs
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
curl -fsS https://<hostname>/healthz
```

### Upgrades

```bash
git pull
make up-prod          # rebuilds the image; migrations run at container start
```

Rollback: `git checkout <previous-tag> && make up-prod`. Migrations are forward-only; if a release
contains a destructive migration, take a backup first and restore it if the rollback needs it.

### Backups (minimum viable, hardened in Phase 12)

```bash
# Database
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T db \
  pg_dump -U "$POSTGRES_USER" -Fc "$POSTGRES_DB" > rhp-$(date +%F).dump

# Media
docker run --rm -v rhp_media_data:/media -v "$PWD":/backup alpine \
  tar czf /backup/rhp-media-$(date +%F).tar.gz -C /media .

# Restore
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T db \
  pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean < rhp-2026-09-30.dump
```

Copy both artifacts **off the machine** (NAS, object storage, or another host). An untested backup is
not a backup: practise the restore on a scratch stack before trusting it. Phase 12 adds scheduling,
retention, encryption, and a documented disaster-recovery procedure.

## Volumes and data location

| Volume | Contents | Losing it means |
| --- | --- | --- |
| `pgdata` | PostgreSQL cluster | all tenant, lease, and financial data |
| `media_data` | Uploaded documents and photos | all tenant files |
| `static_data` | Collected static files | nothing — regenerated by `collectstatic` |
| `caddy_data` | TLS certificates and ACME account | certificates are re-issued |

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `POSTGRES_PASSWORD is not set` | No `.env`: run `make env`. |
| `docker: unknown command: docker compose` | Compose v2 plugin missing: `sudo apt-get install docker-compose-v2`, or run with `COMPOSE=docker-compose`. |
| Container unhealthy, `/healthz` 503 | Database unreachable: check `docker compose logs db` and credentials. |
| Endless redirects to HTTPS | `SECURE_SSL_REDIRECT` on without a TLS-terminating proxy: set both TLS variables consistently (production settings refuse to boot on the unsafe combination). |
| `DisallowedHost` | Hostname missing from `DJANGO_ALLOWED_HOSTS`. |
| CSRF failure on sign-in | Hostname missing from `DJANGO_CSRF_TRUSTED_ORIGINS` (scheme included). |
| Static files 404 | `collectstatic` did not run: check `make prod-logs`, then restart the stack. |
| `exec: "/app/docker/entrypoint.sh": permission denied` | The development bind mount lost the executable bit (also happens on Windows/Samba shares that do not carry Unix modes): `chmod +x docker/entrypoint.sh`. |
| `exec: "/app/docker/entrypoint.sh": no such file or directory` (or an empty `/app`) | The Docker daemon cannot see the bind-mount path. Run Compose from a checkout that exists on the host filesystem — not from inside a container or a shell with a private `/tmp` mount namespace. |
| A second checkout steals the first one's stack | `docker-compose.yml` pins `name: rhp`, so every checkout on a host shares one Compose project and one set of volumes. Give the second checkout its own project: add `COMPOSE_PROJECT_NAME=rhpclone` to its `.env`, or prefix the command. |
| Port 5432 already in use | Another PostgreSQL is running on the host (or a leftover container): `docker ps`, then set `POSTGRES_PORT` in `.env` or remove the other container. |
